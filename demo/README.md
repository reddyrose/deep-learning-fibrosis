# Participant-free synthetic demonstration

A single Jupyter notebook, [`demo_walkthrough.ipynb`](demo_walkthrough.ipynb),
that walks through every stage of the pipeline (`01_imaging` through
`08_clinical_associations`) on fully synthetic data, using code that mirrors
the structure of the original scripts as closely as possible, including a
Grad-CAM visualization of the VAE's latent dimensions, a GWAS Manhattan
plot, and a PWAS phenotype x protein heatmap. Markdown cells narrate each
step; code cells and their output (plots, tables, printed statistics) are
committed inline, so the whole analysis can be read on GitHub without
running anything.

**This demonstrates that the code runs correctly end to end and explains
what each stage's output represents. It is not a reproduction of the
manuscript's results** -- the synthetic cohort is 320 subjects (vs. 50,239
in the real study), the imaging models train for a handful of epochs on
~40 synthetic images (vs. 200 epochs on 42,083 real images), and the
MR/colocalization stages reimplement the same standard statistical formulas
the original R packages (`TwoSampleMR`, `MendelianRandomization`, `coloc`)
use, in Python, to keep the demo to a single environment. None of the
notebook's numbers should be cited as scientific results.

## Why this demo uses synthetic data, not real UK Biobank data

Every stage of this pipeline operates on UK Biobank imaging, genotype, or
proteomic data (application 22282). UK Biobank's data-sharing terms
prohibit redistributing participant-level data or any subset/derivative of
it outside the approved application, which rules out shipping even a small
real extract alongside this repository. See the root
[`README.md`](../README.md)'s **Data availability** section. This notebook
uses exclusively procedurally generated synthetic data instead.

## Run it

```bash
pip install -r ../requirements-demo.txt
jupyter notebook demo_walkthrough.ipynb
```

Or execute it non-interactively and check it reproduces the committed
outputs:

```bash
jupyter nbconvert --to notebook --execute demo_walkthrough.ipynb
```

Measured runtime: about 3 minutes end to end on a standard laptop CPU (no
GPU required -- the synthetic data and training loops are small enough to
run on CPU alone; most of the time is the CVAE training cell, run long
enough for its latent dimensions to differentiate spatially). The
notebook's own summary cell reports the actual measured time for that run.

## `example_data/`

Every input file is procedurally generated by
[`generate_synthetic_data.py`](generate_synthetic_data.py) with a fixed
random seed (42) -- re-running that script regenerates the files
byte-for-byte. See [`example_data/README.md`](example_data/README.md) for
the full data dictionary and [`example_data/SHA256SUMS.txt`](example_data/SHA256SUMS.txt)
for checksums. No file contains UK Biobank data, a real participant
identifier, a real genetic variant, or a real protein name.

The synthetic T1 values are calibrated to the manuscript's actual
acquisition protocol -- 1.5T, ShMOLLI (MAGNETOM Aera; see Piechnik et al.
2010, *J. Cardiovasc. Magn. Reson.* 12, 69) -- centered at 960ms, not an
arbitrary placeholder value.

## Real trained model weights

The repository separately includes the actual reported trained checkpoints
([`01_imaging/myocardium-unet-256.h5`](../01_imaging/myocardium-unet-256.h5),
[`02_vae/cvae_16d_best.weights.h5`](../02_vae/cvae_16d_best.weights.h5)) for
reference and reproducibility. This demo notebook does not load them: a
model trained exclusively on real MRI texture statistics does not produce
meaningful output on procedurally-generated synthetic images (verified
directly -- prediction confidence stays uniformly low across the image,
regardless of added noise/texture). That's expected out-of-distribution
behavior for a deep segmentation network, not a bug in the synthetic data.
The notebook trains and deploys a fresh toy model on the synthetic data
instead, to demonstrate that the training/deployment code itself is correct.
